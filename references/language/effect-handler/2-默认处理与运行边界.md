# 2. 默认处理与运行边界

[← 效应处理器](index.md)

没有匹配 handler 时，运行时调用命令对象的 `defaultImpl()`。子类未重写该方法时，基类实现抛出 `UnhandledCommandException`；因此需要“可脱离 handler 运行”的效应应显式提供默认实现。

例如，`class DefaultNumber <: Command<Int64>` 可以重写 `public override func defaultImpl(): Int64 { 7 }`，使 `perform DefaultNumber()` 在没有 handler 时返回 `7`。

每个恢复点只允许恢复一次；重复恢复由运行时以 `DoubleResumeException` 拒绝。1.1.3 还会把 handler 视为可逃逸的闭包：不要直接捕获并修改局部 `var`；需要统计或共享状态时，捕获不可变引用的对象，例如 `AtomicInt64`，再修改对象内部状态。

Effect Handlers 仍是实验特性，公开库不应把其二进制或控制流语义视为跨版本稳定契约。面向非实验调用方时，在边界处封装普通函数或接口。

工具链边界：仓颉 1.1.3 的 `cjc` 在开启上述选项后能编译效应语法，但同版本 `cjfmt` 没有对应实验选项，实测会把 `perform`、`handle`、`resume` 报成语法错误且仍可能返回 0。格式化门禁必须检查诊断文本；在 formatter 支持该语法前，不要让它覆盖包含 Effect Handler 的源文件。
