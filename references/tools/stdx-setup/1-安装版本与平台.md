# 安装、版本与平台选择

[← stdx 安装与项目配置](index.md)

从 Skill 根目录执行以下命令；`<project-root>` 可以是含 `cjpm.toml` 的目录或清单文件本身。

```shell
python scripts/setup_stdx.py --project <project-root>
```

脚本读取 `cjc -v`，以编译器版本选择 stdx release，以编译器 Target 选择发布平台，不按 Python 所在系统猜测。安装位于跨平台解析的 `~/.cangjie/stdx/`，多个项目可复用。

| `cjc -v` 版本 | stdx 发布件 |
|---|---|
| 低于 `1.0.5` | `1.0.4.1` |
| `1.0.5` | `1.0.5.1` |
| `1.1.x` | `1.1.3.1` |
| `1.2.x` | `1.2.0-beta.02.1` |

其他编译器版本没有已验证策略，脚本会拒绝继续。知识库 API 契约仍以仓颉 `1.1.3`、stdx `1.1.3.1` 为准；安装器支持较新工具链不代表本文档覆盖了其 API 差异。

| `cjc -v` Target | 发布平台 |
|---|---|
| `x86_64-w64-mingw32` | `windows-x64` |
| `x86_64-unknown-linux-gnu` | `linux-x64` |
| `aarch64-unknown-linux-gnu` | `linux-aarch64` |
| `x86_64-apple-darwin` | `mac-x64` |
| `aarch64-apple-darwin` | `mac-aarch64` |
| `x86_64-linux-ohos` | `ohos-x64` |
| `aarch64-linux-ohos` | `ohos-aarch64` |

不同 release 的平台资产并不完全相同；脚本核对版本的平台清单，不构造不存在的 URL。发布页为 `https://gitcode.com/Cangjie/cangjie_stdx/releases/v<stdx-version>`，资产名为 `cangjie-stdx-<platform>-<stdx-version>.zip`。若项目曾在缺少或使用其他 stdx 路径时构建，配置后执行 `cjpm clean`，再重新 `cjpm build` 或 `cjpm run`。
