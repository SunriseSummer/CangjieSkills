# 选项、边界与故障定位

[← stdx 安装与项目配置](index.md)

| 需求 | 选项 |
|---|---|
| 使用本地官方 ZIP | `--archive <file.zip> --offline` |
| 使用自定义全局根目录 | `--destination <directory>` |
| 使用共享或预置缓存 | `--cache-dir <directory>` |
| 只安装、不修改项目 | `--no-configure` |
| 配置静态库 | `--linkage static` |
| 预览完整计划 | `--dry-run --json` |
| 强制重新下载和安装 | `--force` |

`--platform` 只用于显式确认，必须与 `cjc -v` Target 一致。离线模式严格禁止网络访问，要求 `--archive` 或缓存中已有有效 ZIP。完整参数以 `python scripts/setup_stdx.py --help` 为准。

| 现象 | 处理 |
|---|---|
| 找不到 `cjc` 或无法解析版本/Target | 加载正确工具链环境，再运行 `cjc -v` 确认。 |
| 版本不受支持或没有目标平台资产 | 不猜测兼容性；选择已验证工具链，或核对该 release 的实际资产。 |
| 下载失败 | 检查 GitCode 可达性；必要时人工下载官方 ZIP 后传给 `--archive`。 |
| ZIP 不安全、损坏或布局异常 | 丢弃并从官方 release 重新获取，不要强制解压。 |
| TOML 无效 | 先修复 `cjpm.toml` 语法，再重跑脚本。 |
| 配置后仍沿用旧依赖 | 执行 `cjpm clean` 后重新构建。 |
| 构建成功但直接运行失败 | 改用 `cjpm run`，或配置动态库搜索路径。 |

`cjpm run` 会处理动态库搜索路径；绕过 cjpm 直接启动产物时，自行把 `dynamic/stdx` 加入 Windows `PATH`、Linux `LD_LIBRARY_PATH` 或 macOS `DYLD_LIBRARY_PATH`。静态链接 crypto/net 可能还需要系统 OpenSSL 或平台链接选项。脚本不安装 OpenSSL，不执行 `cjpm clean/build/run`，也不验证 GitCode 发布签名；记录 SHA-256 用于追溯，不替代官方签名。
