# 第二轮：多路检索、决策树与量化语义模型

[← 项目说明](../README.md) · [第一轮完整记录](retrieval-model.md)

## 目标与评测边界

本轮继续只使用仓颉 `cangjie-1.0.5` 基线的 7605 个活动知识页，输出 `references/...md` 路径，不生成代码或知识答案。原有 Python 查询入口、SQLite 发布件和 Skills 指令保持原有使用方式。

第一轮提交 `e654752` 的 C++ BM25、线性排序器和 66 条评测数据保留为基线。因为已经分析过这些查询，本轮将其视为**开发回归集**，不能再将其提升称为未见查询的泛化收益。

新增合成查询集独立编写并由另一个代理审计，候选实现、参数和模型冻结后才公开和评测。训练数据、旧回归数据和新查询留出数据分别记录哈希。标签列举可直接使用的知识页或明确包含答案的窄索引，按任一相关路径命中统计 Hit@1/5 与 MRR@5；它不是穷尽相关页面集合的 Recall。

## 三条优化路线

| 路线 | 核心变化 | 查询时依赖 | 目的 |
| --- | --- | --- | --- |
| 原生多路检索 | 分开计算元数据与正文证据，融合多个候选通道，逐候选判断匹配证据 | C++17 可执行文件与索引 | 改善长中文问句、概念入口及复合任务，保持轻量 |
| 小型决策树 | 用浅层树组合查询与候选特征，导出为 C++ 常量数组 | C++17，训练时才需 Python 科学计算库 | 检查非线性特征组合是否优于第一轮线性先验 |
| INT8 语义检索 | BGE-small 中文向量召回，与原生结果融合 | 可选 Python、ONNX Runtime、tokenizers、NumPy | 改善意译和词汇不重叠，测量额外 CPU 与内存成本 |

原生通道与树模型运行时不使用 Python 或模型服务。语义通道是独立可选工具，需要额外运行库；不能将它的成本归入“零依赖 C++”描述中。

## 第一轮问题与本轮设计

第一轮的拒答判断依赖排序后的首项，首项证据不足就可能清空全部候选。这样排序错误会放大为漏检，也使线性模型的训练损失下降未能转化为检索收益。本轮将候选证据判断与排序解耦，保留来自不同通道的有效候选。

中文二元组包含大量跨词边界的片段。对整句中的未知二元组逐一扣分，会惩罚包含口语表达的长问题；短查询又容易被正文中的普通词吸引到无关成员。本轮在不改变文档契约的前提下分开处理问题功能词、完整代码标识符、主题词和候选页面类型。

单一加权词频也不能充分区分“标题直接讨论该概念”和“长页面碰巧提到该词”。本轮增加独立的元数据召回证据，再进行多路融合。精确 ID、路径和 API 成员请求仍需保留直接命中的优先级。

## 小模型的含义

决策树学习的是候选相关性特征之间的非线性关系，不直接记忆数千个路径类别。新增文档时重新生成索引即可参与候选检索；是否需要重训取决于任务分布和验证结果。

训练与交叉验证以查询为分组，不能把同一问题的不同候选拆到训练和验证两侧。旧评测查询参与训练或选择参数后，只报告为开发数据表现。得分不称为经过校准的相关概率。

语义通道使用预训练的中文文本编码模型，将问题和文档摘要映射到向量空间。文档向量离线计算；查询时只编码问题，再在本地向量表中检索。精确 API 和重载信息仍由原生符号通道补充。模型下载发生在显式构建阶段，查询时不发送问题或文档到外部服务。

## 运行与复现

从仓库根目录构建原生索引和可执行文件：

```sh
python scripts/maintenance/build_router.py
build/doc_router/cj-doc-router --index build/doc_router/router.idx \
  --strategy hybrid --query "泛型的多个接口约束怎么写" --top-k 5 --explain
```

| 选项 | 含义 |
| --- | --- |
| `--strategy hybrid` | 当前编译默认值，使用第二轮原生多路融合 |
| `--strategy tree` | 使用第二轮小型树模型修正融合分数 |
| `--strategy v1` 或 `--bm25-only` | 第一轮原生 BM25，用于兼容与对照 |
| `--learned-ranker` | 第一轮线性模型，与第二轮树模型不同 |
| `--stdin` | 每行一个查询，进程常驻，避免重复加载索引 |

`--query` 可以重复；`--domain` 保留原知识库的语义领域过滤规则。`--explain` 输出策略、特征版本、得分，树模式还提供模型指纹。索引 v2 添加了独立元数据字段，原生运行时仍能读取 v1 索引。

树模型已经导出为头文件，普通构建不需要安装训练依赖。重新训练时使用 Python、NumPy 2.3.5 和 scikit-learn 1.8.0：

```sh
python scripts/maintenance/train_router_v2.py
python scripts/maintenance/build_router.py
python scripts/maintenance/train_router_v2.py --check
```

本次树模型有 32 棵深度最多为 3 的树、480 个节点，节点表约 15 KiB。使用 13 个特征：12 个候选特征加完整融合基础分。最终分数为 `hybrid_score + 2 × tree_prediction`。修正强度从预定 `{0,1,2,4}` 中按主题分组交叉验证选择，包含完全保留基础排序的选项 0。

训练使用 36 条原开发查询与第一轮 66 条查询，共 102 条；未使用第二轮新留出集。单独树排序在分组验证中更差，保留基础分的校正才获得小幅收益。完整候选验证、分组、参数和数据哈希见 `native/doc_router/model/tree_ranker.json`。这不是残差目标回归，也不输出校准概率。

可选语义路径需要单独安装依赖和下载模型：

```sh
python -m pip install -r native/doc_router/semantic/requirements.txt
python scripts/maintenance/build_semantic_router.py --download
python scripts/semantic_router.py --mode hybrid --query "泛型的多个接口约束怎么写" --top-k 5
```

模型文件共 24,343,235 字节，512 维文档向量文件 15,575,168 字节，另有约 2 MB 文档元数据。下载绑定固定仓库版本、文件长度和 SHA-256；模型权重和生成向量不提交 Git。语义源码、依赖版本、使用说明和许可证来源见 [语义模块说明](../native/doc_router/semantic/README.md)。

查询程序在导入 ONNX Runtime 前设置 `ORT_DISABLE_TELEMETRY=1`，并调用遥测关闭 API。对已经以未关闭状态加载推理库的进程拒绝继续初始化。这是根据 ONNX Runtime 1.32.0 安装包附带的 `Privacy.md` 处理初始化遥测：单独调用 API 不足以阻止最早的初始化事件。构建器只有显式 `--download` 阶段下载文件，查询不下载或调用模型服务。

语义混合路径将语义结果作为低权重补充通道，中文概念优先从语言、工具和示例知识页召回，精确 API 所属关系保留原生证据。相似度阈值是未校准的经验门槛，不能将余弦分数当作问题可回答概率。

```sh
python scripts/maintenance/build_router.py --check
python scripts/maintenance/build_semantic_router.py --check
python scripts/evaluation/evaluate_router_v2.py --include-tree \
  --semantic-index build/semantic-router --output reports/router-evaluation-v2.json
```

评测器可用新程序的 `--strategy v1` 复现第一轮词汇排序，也支持保存的第一轮程序；协议测试核对了归档程序全部 66 条结果完全一致。语义向量是浮点推理结果，检查验证来源与文件哈希，不承诺跨平台重新计算时逐位相同。

## 新留出查询上的结果

第二轮新增 94 条查询，其中 70 条正例、24 条无关或知识库不支持的查询。它们在实现与参数冻结前没有交给优化代理；既没有参与树模型训练，也没有用于调整规则或语义阈值。该数据仍是独立代理生成并审计的合成集，不等于真实用户流量。完整逐题结果与数据、模型指纹见 [第二轮原始报告](data/router-evaluation-v2.json)。

| 方案 | 正例 Hit@5 | 负例正确拒绝 |
| --- | ---: | ---: |
| 原 Python | 38/70，54.29% | 11/24，45.83% |
| 第一轮原生 BM25 | 44/70，62.86% | 18/24，75.00% |
| 第二轮原生多路融合 | 56/70，80.00% | 13/24，54.17% |
| **第二轮融合 + 小型树修正** | **58/70，82.86%** | 13/24，54.17% |
| INT8 语义混合 | 56/70，80.00% | 13/24，54.17% |
| 纯向量，阈值 0.65 | 26/70，37.14% | 21/24，87.50% |
| 纯向量，不设阈值 | 33/70，47.14% | 0/24，0.00% |

主要收益来自新的原生多路召回与融合；小型树模型在此基础上多覆盖 2 条正例。树模式的首项命中为 33/70，第一轮原生为 30/70；MRR@5 分别为 0.6036 和 0.5190。路径列表中仍可能先出现不够直接的页面，不能把前 5 项命中等同于首次读取即可解决问题。

这次提升伴随拒答能力下降：无关或不支持查询的误检由第一轮 6/24 增加到 11/24。当前逐候选门控更愿意保留部分相关证据，不能判断知识库是否足以解答整个问题。适合已确认属于仓颉知识库的开发查询；需要更保守的无匹配行为时，保留 `--strategy v1` 作为可选模式。

纯向量在不设阈值时也只命中 33/70，说明低表现既来自保守阈值，也来自候选排序噪声。为混合路线选出的 0.65 阈值不是单独为纯向量优化的最佳阈值；无阈值路线作为固定诊断对照一同评测。当前语义混合没有超过原生路线，不推荐为默认检索增加这部分依赖与运行成本。

新查询已经公开，后续分析这些失败样例后，它们将成为回归数据；再评估新模型的泛化需要另设留出集。

| 正例类型 | 数量 | 第一轮原生 Hit@5 | 树模式 Hit@5 |
| --- | ---: | ---: | ---: |
| 精确符号 | 14 | 14/14 | 14/14 |
| 自然问句 | 18 | 5/18 | 11/18 |
| 概念问题 | 16 | 9/16 | 13/16 |
| 复合任务 | 10 | 9/10 | 10/10 |
| 错误诊断 | 12 | 7/12 | 10/12 |

树模式相对第一轮在前 5 项命中上新增 14 题、丢失 0 题；首项命中新增 7 题、丢失 4 题。主要收益集中在自然问句、概念问题和错误诊断，精确符号结果保持稳定。

## CPU 与内存成本

测试环境为 Linux x86_64、AMD EPYC 9V74、Python 3.12.14、g++ 14.2.0。语义路线固定 ONNX、OpenBLAS、OMP 单线程。冷进程只表示重新启动进程，未清理文件缓存；冷进程墙钟时间取 3 次中位数，常驻查询预热一次后依次执行 70 条新正例。

| 方案 | 冷进程单查询 | 常驻中位数 / P95 | 冷进程峰值 RSS |
| --- | ---: | ---: | ---: |
| 原 Python | 368.948 ms | 未测量 | 51.59 MiB |
| 第一轮原生 | 58.587 ms | 1.606 / 5.185 ms | 24.14 MiB |
| 第二轮原生融合 | 89.696 ms | 1.953 / 5.884 ms | 31.39 MiB |
| 第二轮树修正 | 78.815 ms | 2.129 / 6.564 ms | 31.39 MiB |
| INT8 语义混合 | 343.303 ms | 16.934 / 25.242 ms | 115.04 MiB，另有原生子进程 |

当前树模式仍适合 CPU 轻量运行：额外模型节点表约 15 KiB，完整索引 8,431,841 字节，查询不需要 Python 或推理框架。冷启动样本较少且有调度波动，不能据表中小差异判断树推理比基础融合更快。

内存由独立的最小标准库辅助进程启动被测程序，再读取其 `wait4` 资源使用量。这样避免大型评测脚本在 fork 时将自身占用计入子进程峰值。内存探测与原墙钟测量分开记录，不能用内存探测的耗时替换性能表。语义混合的 RSS 不包含并发原生子进程总和，后者还需约 31 MiB。

Python 原入口输出更多摘要、签名和契约元数据，原生入口主要输出路径，时间差包含输出工作量差异。所有数字是本机测试，不代表低功耗开发板表现。

## 建议使用方式与验证

对已确认属于仓颉知识库的编码问题，建议显式使用 `--strategy tree` 获取较高覆盖率；需要减少无关查询误检时可选择 `--strategy v1`。编译默认保留 `hybrid`，供稳定的无训练融合路线使用。语义模型作为可复现实验保留，当前不推荐作为默认部署依赖。

本轮主回归、第二轮兼容与评测协议测试均通过，1 项既有环境条件测试跳过；另有 7 项可选语义协议、隐私和向量归一化测试通过。原知识库构建检查、原生和语义索引检查、旧线性模型与新树模型训练复现检查均通过。知识结构检查仍为 7605 条记录、17885 个链接，无警告或错误。

后续要同时改善召回与无关拒答，应把“候选相关性排序”和“知识库是否覆盖整个问题”作为两个独立目标，增加版本混淆、邻近但不支持 API 等训练与验证数据。仅调整现有一个分数阈值，容易再次以漏掉有用文档换取拒答率；这次报告保留了该取舍供后续独立验证。
